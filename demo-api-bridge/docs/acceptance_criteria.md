# 検収条件

## PASS条件
1. **スキーマ検証**: 旧形式スキーマに違反するペイロードは拒否(422)され、upstreamへ転送されないこと。
2. **冪等性**: 同一の`Idempotency-Key`を持つ複数のリクエストは、upstreamへの重複リクエストを発生させないこと。キャッシュされたレスポンスが返されること。
3. **マッピングの外部化**: フィールドマッピングのロジックは外部設定(`input/mapping_rules.json`)から読み込まれ、ハードコードされていないこと。
4. **レジリエンス**: Bridgeはupstreamの5xxおよび接続エラーを設定された上限回数までリトライするが、4xxエラーはリトライしないこと。
5. **タイムアウト制御**: upstreamが設定した時間制限を超えた場合、Bridgeはリクエストを中断し504 Gateway Timeoutを返すこと。
6. **ログのマスキング**: 機密フィールド(`api_key`、`password`等の認証情報に加え、`full_name`、`tel`等の個人情報)は構造化ログからマスキングされること。マスキング対象は認証情報に限定しない。
7. **Redisの認証**: Redisは無認証で待ち受けないこと。接続にはパスワードが必須であること。
8. **テストカバレッジ**: `pytest tests/`の実行結果が100% PASSであること。
9. **再現性**: 環境全体(Bridge、Redis、Upstreamモック)は`docker-compose up`のみで完全に再現できること。

## 対象外
* **複雑なメッセージブローカー**: モジュールを厳密に疎結合に保つため、Kafka、RabbitMQ、複雑なDead Letter Queue(DLQ)は含みません。
* **認証プロバイダ**: Bridgeは標準的なヘッダーに依存し、OAuthトークン自体の発行は行いません。
